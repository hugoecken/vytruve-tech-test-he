# Data Model: Orthoprosthetist Printing Workflow

**Status**: Accepted

PostgreSQL owns relational integrity. Liquibase XML owns schema creation and evolution. TypeORM entities mirror the resulting schema for runtime mapping only.

## Conventions

- Table and column names use `snake_case`.
- Primary keys use database-generated UUIDs.
- Timestamps use timezone-aware PostgreSQL values and are serialized as ISO 8601 UTC strings.
- Public list ordering is always `created_at DESC, id DESC`.
- Foreign keys are non-null unless explicitly marked otherwise.
- Owner-scoped indexes start with the ownership or parent key, then ordering columns.
- No entity is serialized directly to HTTP.

## Account

Represents one orthoprosthetist identity and the root ownership boundary.

| Column | Type | Null | Rules |
| --- | --- | --- | --- |
| `id` | `uuid` | No | Primary key; generated by PostgreSQL |
| `email` | `varchar(320)` | No | Trimmed, case-normalized value; unique |
| `password_hash` | `varchar(255)` | No | Encoded Argon2id result; never public |
| `created_at` | `timestamptz` | No | Database creation timestamp |

### Constraints and indexes

- `pk_account` on `id`.
- `uq_account_email` on normalized `email`.
- No plaintext password, language preference, session row, or refresh token is stored.

## Patient

Represents the minimal patient record owned by one account.

| Column | Type | Null | Rules |
| --- | --- | --- | --- |
| `id` | `uuid` | No | Primary key |
| `account_id` | `uuid` | No | Foreign key to `account.id` |
| `first_name` | `varchar(100)` | No | Trimmed, non-empty Unicode text |
| `last_name` | `varchar(100)` | No | Trimmed, non-empty Unicode text |
| `age` | `smallint` | No | Integer from 0 through 150 |
| `created_at` | `timestamptz` | No | Database creation timestamp |

### Constraints and indexes

- `pk_patient` on `id`.
- `fk_patient_account` references `account(id)` with restrictive deletion behavior.
- `ck_patient_age` requires `age BETWEEN 0 AND 150` because this scalar invariant is stable and safety-relevant.
- `ix_patient_account_created` on `(account_id, created_at DESC, id DESC)` supports owner-scoped ordered pages and member lookup.

Patient names and age are never copied into scans, print requests, pagination metadata, storage keys, or logs.

## Scan

Represents metadata for one validated PLY object stored privately in MinIO.

| Column | Type | Null | Rules |
| --- | --- | --- | --- |
| `id` | `uuid` | No | Primary key and safe public identifier |
| `patient_id` | `uuid` | No | Foreign key to `patient.id` |
| `storage_key` | `varchar(128)` | No | Unique opaque random key; never public |
| `format` | `varchar(16)` | No | `ply` |
| `encoding` | `varchar(32)` | No | `ascii`, `binary_little_endian`, or `binary_big_endian` |
| `size_bytes` | `integer` | No | From 1 through `26_214_400` |
| `created_at` | `timestamptz` | No | Database creation timestamp |

### Constraints and indexes

- `pk_scan` on `id`.
- `fk_scan_patient` references `patient(id)` with restrictive deletion behavior.
- `uq_scan_storage_key` prevents object-key aliasing.
- `ck_scan_size` requires `size_bytes > 0 AND size_bytes <= 26214400`.
- `ix_scan_patient_created` on `(patient_id, created_at DESC, id DESC)` supports parent-scoped pages and member lookup.

The original filename, browser MIME value, MinIO endpoint, bucket, ETag, and object URL are not persisted because the product does not require them.

## Print Request

Represents one physical printing attempt for a scan and its last validated provider observation.

| Column | Type | Null | Rules |
| --- | --- | --- | --- |
| `id` | `uuid` | No | Primary key |
| `scan_id` | `uuid` | No | Foreign key to `scan.id` |
| `reference` | `varchar(12)` | No | Unique system-generated uppercase-safe reference |
| `provider_id` | `varchar(128)` | Yes | Validated provider identifier when known; never public |
| `status` | `varchar(32)` | No | One canonical public state |
| `active_slot` | `boolean` | Yes | `true` for non-terminal states; `null` for terminal states |
| `scheduled_start_at` | `timestamptz` | Yes | Last validated planned production start |
| `scheduled_end_at` | `timestamptz` | Yes | Last validated planned production end |
| `last_observed_at` | `timestamptz` | Yes | Time of the last validated provider observation |
| `created_at` | `timestamptz` | No | Local request creation timestamp |
| `updated_at` | `timestamptz` | No | Last local state-change timestamp |

### Canonical status values

- `confirmation_pending`
- `queued`
- `in_progress`
- `completed`
- `failed`

### Constraints and indexes

- `pk_print_request` on `id`.
- `fk_print_request_scan` references `scan(id)` with restrictive deletion behavior.
- `uq_print_request_reference` on `reference`.
- `uq_print_request_active_slot` on `(scan_id, active_slot)`.
- `ck_print_request_active_slot` requires:
  - `active_slot = true` for `confirmation_pending`, `queued`, and `in_progress`;
  - `active_slot IS NULL` for `completed` and `failed`.
- `ix_print_request_scan_created` on `(scan_id, created_at DESC, id DESC)` supports scan history.
- `ix_print_request_status_observed` on `(status, last_observed_at)` is added only if the planned active-read query needs it during implementation; it is not part of the baseline by default.

The unique slot rejects concurrent attempts to reserve a second non-terminal request for one scan. PostgreSQL permits multiple `(scan_id, NULL)` rows, so completed and failed history remains append-only.

## Relationships

```text
account 1 ─── 0..* patient 1 ─── 0..* scan 1 ─── 0..* print_request
```

- Account ownership reaches scans and print requests transitively through patient.
- Protected queries join or constrain through the full owner path before returning data.
- The MVP exposes no deletion. Foreign keys therefore use restrictive behavior and do not imply hidden cascade semantics.

## Print Request State Machine

```text
                         definite capacity rejection
                         ┌──────────────────────────► no persisted request
                         │
confirmation_pending ────┼──► queued ───► in_progress ───► completed
         │               │       │              │
         │               │       └──────────────┴────────► failed
         │               │
         └── ambiguous ──┘  remains confirmation_pending until reconciled
```

### Transition rules

| From | To | Required evidence |
| --- | --- | --- |
| No request | `confirmation_pending` | Local reference and active reservation persist before provider POST |
| `confirmation_pending` | `queued` | Valid provider response confirms a job whose production has not started |
| `confirmation_pending` | `in_progress` | Valid provider response confirms active production |
| `confirmation_pending` | `completed` | Valid provider lookup confirms success |
| `confirmation_pending` | `failed` | Valid provider lookup confirms terminal failure |
| `queued` | `in_progress` | Confirmed production start is reached or provider reports active production |
| `queued` | `completed` or `failed` | Provider confirms a terminal outcome |
| `in_progress` | `completed` or `failed` | Provider confirms a terminal outcome |

- `completed` and `failed` are terminal for that request.
- A new request may be reserved for the same scan only after the previous request becomes terminal.
- An unknown, malformed, unavailable, or ambiguous provider response never produces `completed`.
- The application never transitions backward from a terminal state.

## Estimated Progress Projection

Estimated progress is computed when mapping a print-request view and is never stored.

| Status | Projection |
| --- | --- |
| `confirmation_pending` | `null` |
| `queued` | `0` |
| `in_progress` with usable start and end | `floor(elapsed / duration * 100)`, clamped to `0…99` |
| `in_progress` without a usable interval | `0` or the last safely derivable value, never above `99` |
| `completed` | `100` |
| `failed` | `null` |

All date arithmetic uses UTC instants. Scheduled dates are provider observations, not guarantees.

## Server Pagination Model

Pagination state is transport input, not a database entity:

```text
page
pageSize
```

- `page` is zero-based and defaults to `0`.
- `pageSize` defaults to `20` and is bounded between `1` and `50`.
- Queries remain owner-scoped, ordered by `created_at DESC, id DESC`, and use `skip = page * pageSize` with `take = pageSize + 1`.
- The look-ahead row determines `hasNext`; responses do not execute a total-count query or invent a page count.

## Scan Storage Consistency

### Upload success

1. Authorize the patient with an owner-scoped query.
2. Enforce the byte bound and validate the PLY structure.
3. Generate one opaque object key.
4. Write the object to the private MinIO bucket.
5. Persist scan metadata.
6. Return the mapped public response.

### Persistence failure after object write

1. Retain the exact generated key in local operation scope.
2. Remove only that object.
3. Report cleanup failure once as an operational error without exposing the key.
4. Return no successful scan representation.

There is no generic orphan sweeper, outbox, queue, or distributed transaction in this MVP.

```text
database/db.changelog-master.xml
├── changelog/001-accounts-patients.xml
├── changelog/002-scans.xml
└── changelog/003-printing.xml
```

- The master contains ordered `<include>` elements and no business data.
- The initial pre-deployment baseline uses standard Liquibase changes wherever possible.
- Each constraint and index has an explicit stable name.
- No sample account, patient, scan, print request, credential, or provider data is seeded.
- After any retained environment applies the baseline, later changes append new change sets instead of editing applied history.
