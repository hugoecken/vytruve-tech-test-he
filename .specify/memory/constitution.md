# Vytruve Spec Kit Constitution

## Repository Authority First

`AGENTS.md` governs every agent and routes work to the repository's policies, overlays, and source evidence.
This constitution is a concise Spec Kit adapter and never overrides or duplicates those authorities.

## Accepted Intent Before Implementation

The supplied brief owns non-negotiable source requirements. An explicitly accepted `spec.md` snapshot owns future
observable behavior. Approved Figma evidence may compose that behavior visually without expanding it. The matching
approved `plan.md` owns technical translation, while `tasks.md` remains a derived checklist.

## GitHub Execution Authority

GitHub issues own priority, dependencies, assignment, scope, and delivery state. Pull requests own review of an exact
head. Spec Kit must not create competing issues, branches, tasks, statuses, reviews, merges, releases, or Figma state.
Acceptance and implementation authorization remain explicit human decisions.

## Runtime And Evidence Authority

Current source, contracts, migrations, generated outputs, and tests own delivered executable behavior. Review and
conformance evidence applies only to the exact head and accepted binding it names. Missing or ambiguous intent,
acceptance, plan, source, scope, or validation authority fails closed.

## Managed Artifacts And Protected Data

Core Spec Kit skills, scripts, templates, workflows, and manifests remain generated and upgradeable. Repository
adaptation uses supported presets and overlays. Local feature selection owns no shared state. Secrets,
contacts, credentials, personal data, scan content, and runtime artifacts never enter committed evidence.

## Governance

Constitution changes require explicit GitHub scope, review, and the validation selected by repository guidance.
Changing this document cannot change runtime behavior or silently accept product or architecture decisions.
